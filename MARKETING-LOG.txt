1. PRODUCT IDENTITY & MISSION
--------------------------------------------------------------------------------
swarm-ai is a local-first Python toolkit for parallel LLM and Claude agent
orchestration. It provides inspectable, deterministic implementations of five
fundamental multi-agent coordination patterns:
  1. Parallel Chunks Pattern (split, concurrent execution, atomic merge)
  2. Boss / Worker Hierarchy (central coordination, isolated failure boundaries)
  3. Stigmergy & Pheromone Store (indirect SQLite-backed marker coordination)
  4. Consensus & Majority Vote (independent multi-model verification, confidence)
  5. Specialist Routing (JSON-defined skill & domain expert routing)

Unlike heavy enterprise agent frameworks (CrewAI, LangGraph, AutoGen) or hosted
SaaS platforms, swarm-ai is 100% local-first, runs in standard unprivileged user
mode (RunAsInvoker), and enforces fail-closed budgeting with zero external
telemetry.

2. TARGET PERSONAS & AUDIENCE MAPPING
--------------------------------------------------------------------------------
Persona 1: Autonomous Coding Agent Operators (Claude Code, Gemini, Codex)
  - Need: Running subagents and multi-model consensus checks without crashing or
    violating filesystem locks.
  - Value: Portable Team Lock guardrail (tools/team_lock.py) prevents write
    collisions; dry-run mode allows cost-free preflight verification.

Persona 2: Local-First AI Application Engineers
  - Need: High-throughput document translation and chunked summarization.
  - Value: Proven 2.54x speedup via parallel Anthropic / Claude CLI fan-out with
    automatic SQLite claim recovery.

Persona 3: AI Safety & Governance Researchers
  - Need: Empirical evaluation of multi-model agreement and hallucination reduction.
  - Value: Deterministic consensus voting with mathematically transparent agreement
    percentages, vote distributions, and confidence scoring.

Persona 4: Distributed Systems & Stigmergy Experimenters
  - Need: Decoupled agent communication where agents coordinate through their
    environment rather than direct RPC/P2P chatter.
  - Value: SQLite-backed stigmergy API with pheromone deposition, sensing, decay,
    and evaporation.

3. ARCHITECTURAL INVARIANTS & GOVERNANCE
--------------------------------------------------------------------------------
The project adheres to 10 strict runtime invariants (INV-LOCAL-01 to INV-SLA-10):
  - INV-LOCAL-01: 100% Local-First & Zero-Egress (no tracking, local SQLite)
  - INV-RUNAS-02: Unprivileged User Mode (RunAsInvoker, zero elevated rights)
  - INV-BUDGET-03: Fail-Closed Budgeting (strict USD, token, and call limits)
  - INV-STORE-04: SQLite Stigmergy Store (atomic transactions, schema stability)
  - INV-CHUNKS-05: Parallel Chunks Pattern (deterministic key/namespace merge)
  - INV-HIERARCH-06: Boss / Worker Hierarchy (isolated worker error domains)
  - INV-VOTE-07: Consensus & Majority Vote (statistical confidence & voting)
  - INV-ROUTER-08: Specialist Routing & COMA Bridge (modular provider routing)
  - INV-LOCK-09: Team Lock Guardrail (concurrency & race-condition prevention)
  - INV-SLA-10: 48h Security Response & 5-Day Triage SLA (SECURITY.md)
